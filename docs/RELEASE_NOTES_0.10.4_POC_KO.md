# Samsung Switch Watch 0.10.4-poc 릴리스 노트

이번 버전은 Agent Setup이 자동 검색하지 못한 승인된 스위치 관리망을 운영자가 직접 추가할 수
있도록 개선합니다. 자동 검색은 계속 기본 경로이며, 공인망이나 임의의 넓은 범위를 허용하는
기능은 추가하지 않았습니다.

## 사용자 흐름

1. Agent Setup에 Viewer PC의 고정 RFC1918 IPv4 한 개를 입력합니다.
2. 자동 검색된 스위치 관리망을 우선 선택합니다.
3. 승인된 관리망이 목록에 없으면 `IPv4/prefix` 형식으로 한 개씩 직접 추가합니다.
4. 자동 선택과 직접 추가를 합해 서로 다른 관리망 1~2개를 확정합니다.
5. `사전 점검`을 통과한 뒤 기존 `설치 / 업데이트` 버튼을 사용합니다.

직접 입력한 호스트 주소는 canonical 네트워크 주소로 정규화됩니다.

```text
입력: 10.50.0.10/24
적용: 10.50.0.0/24
```

## 관리망 입력 제한

- strict dotted IPv4와 prefix가 모두 있어야 합니다.
- 정규화된 네트워크 전체가 RFC1918 사설망 범위 안에 있어야 합니다.
- 공인망과 RFC1918 경계를 벗어나는 넓은 범위는 거부합니다.
- 자동 검색 항목과 직접 추가 항목은 정규화된 CIDR 기준으로 중복을 거부합니다.
- 자동 선택과 직접 추가를 합해 세 번째 관리망은 허용하지 않습니다.
- 최종 `AllowedTargetCidrs`에는 서로 다른 canonical RFC1918 CIDR 1~2개만 저장합니다.

관리망을 직접 추가해도 Agent의 장비 접속은 해당 범위의 canonical IPv4와 Telnet/TCP 23으로
제한됩니다. Viewer와 Agent 양쪽의 한 줄 `show` 명령 정책도 그대로 유지됩니다.

## 기존 설정 복원

기존 Agent 설정에 서로 다른 canonical RFC1918 `AllowedTargetCidrs`가 1~2개 있으면 Setup이
이를 같은 관리망 목록에 복원하고 선택 상태로 표시합니다.

대상 목록이 없거나 불완전하거나 중복되어 안전하게 복원할 수 없으면
`SETUP_EXISTING_NETWORKS_NOT_LOADED` 경고를 표시하고 아무 관리망도 미리 선택하지 않습니다.
이 경고만으로 설치를 영구 차단하지는 않습니다. 운영자가 자동 검색 결과를 다시 선택하거나
승인된 CIDR을 직접 추가한 뒤 검사와 설치를 계속할 수 있습니다. 전체 운영 설정 JSON 자체가
손상된 경우에는 별도의 기존 배포 설정 검증이 설치를 차단할 수 있습니다.

## 유지되는 보안 동작

- Viewer→Agent는 HTTPS/TCP 18443을 사용합니다.
- 제품 소유 방화벽 규칙과 Agent API는 같은 고정 Viewer IPv4 한 개를 확인합니다.
- 다른 프로그램 소유의 TCP/18443 인바운드 규칙은 삭제·비활성화·변경하지 않습니다.
- Agent→스위치는 Setup에서 확정한 관리망과 Telnet/TCP 23만 허용합니다.
- 인증서 SHA-256 지문과 페어링 토큰을 사용자가 입력하는 절차는 없습니다.
- 운영 장비 설정을 변경하지 않으며 읽기 전용 `show` 명령만 사용합니다.

## 호환성과 검증

- Agent와 Viewer는 같은 `0.10.4-poc` Release의 ZIP을 함께 사용하십시오.
- 장비 API, Viewer 장비·자격 증명 저장 형식과 Telnet 실행 요청 형식은 변경하지 않았습니다.
- 자동 검색, 수동 CIDR 정규화, 중복·공인망·세 번째 범위 거부와 기존 설정 복원은 합성 입력과
  Mock으로 검증합니다.
- Mock 통과를 실제 삼성 스위치, 사내 라우팅, 방화벽·EDR 또는 그룹 정책 검증으로 간주하지
  않습니다.
- 직접 추가한 관리망은 사내에서 승인된 라우팅과 Agent PC→장비 TCP/23 경로를 먼저 확인해야
  합니다.
