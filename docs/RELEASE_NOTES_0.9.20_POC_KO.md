# Samsung Switch Watch 0.9.20-poc 릴리스 노트

## 장비 변경 중 늦게 도착한 감시 결과 격리

- 장비 감시를 끄거나 장비를 삭제한 뒤 이전 Telnet 요청이 늦게 완료되어도 그 결과를
  현재 상태, 수집기 지원 상태 또는 장애 이력으로 저장하지 않습니다.
- 장비 IP, 모델, ID, 로그인 PW 또는 enable PW가 변경되면 이전 요청의 성공·실패·인증
  실패 결과를 폐기합니다.
- 이전 인증정보로 시작한 요청의 `AUTH_FAILED`가 늦게 도착해도 새 인증정보를 비검증
  상태로 되돌리거나 감시를 차단하지 않습니다.
- 장비별 요청을 시작할 때의 수명주기 번호와 현재 장비 정의를 저장 직전과 화면 반영
  직전에 함께 확인합니다.

## 기준선과 현재 장애 상태 초기화

- 접속 대상이나 인증정보가 변경되면 이전 포트 상태 기준선, 명령 지원 상태, 활성 접속
  실패와 활성 포트 장애를 한 번의 원자적 저장으로 정리합니다.
- 감시를 껐다가 다시 켤 때도 이전 버전에서 남은 기준선을 제거하므로 첫 수집 결과를
  과거 상태와 비교해 허위 `Up → Down` 장애를 만들지 않습니다.
- 기존 장애 이력은 삭제하지 않고 확인·종료 상태로 보존합니다.
- 저장 실패 시 메모리와 파일의 일부만 변경되지 않도록 전체 변경을 롤백합니다.

## Agent 연결 상태와 화면 일관성

- 장비를 편집·비활성화·삭제하는 순간 Agent 통신 자체가 실패하면 장비별 결과는
  폐기하되 Agent 전체 연결 실패는 Viewer에 계속 표시합니다.
- 장비 이름만 변경하는 동안 감시 이벤트가 저장된 경우에도 저장소의 최신 이벤트를
  다시 읽어 대시보드와 파일 상태가 어긋나지 않게 합니다.

## 호환성과 운영 영향

- Agent API v4, Viewer 설정, 장비 저장 JSON과 감시 이력 JSON 스키마는 변경하지
  않았습니다.
- 조회 명령, 5분 기본 감시 주기, 장비당 세션 제한, 동시 감시 제한과 Telnet 세션 종료
  방식은 변경하지 않았습니다.
- 화면 구성과 Agent·Viewer 설치 순서는 변경하지 않았습니다.
- 기존 Agent와 Viewer를 같은 릴리스의 ZIP으로 함께 업데이트하는 절차를 그대로
  사용합니다.

## 검증

- 감시 중 비활성화·삭제·접속정보 변경, 늦은 인증 실패, 재활성화 후 첫 기준선,
  장비 변경과 동시에 발생한 Agent 전체 연결 실패를 결정적 테스트로 검증했습니다.
- Core 85건, Agent 53건, Viewer 281건으로 총 419건의 자동 테스트를 통과했습니다.
- Release 빌드 경고·오류 0, C# 서식, PowerShell 5.1 구문·설치·복구 계약, NuGet
  취약 패키지와 Git whitespace 검사를 통과했습니다.

## 보안과 현장 검증 범위

- Agent 방화벽은 등록한 Viewer IPv4의 정확한 `/32`, Domain/Private 프로필만
  허용합니다.
- 설치기는 파일 차단 해제, ACL 완화 또는 보안 제품 우회를 수행하지 않습니다.
- 이 `-poc` 패키지는 Authenticode 서명이 없는 현장 검증용 프리릴리스입니다.
- 합성 Telnet 서버와 로컬 계약 테스트로 검증했으며, 실제 사내 EDR·AppLocker·WDAC
  정책과 IES4224GP, IES4028XP, IES4226XP 펌웨어는 현장에서 확인해야 합니다.
