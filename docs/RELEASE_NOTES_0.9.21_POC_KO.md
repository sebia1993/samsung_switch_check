# Samsung Switch Watch 0.9.21-poc 릴리스 노트

## 감시 이력 로드 실패 시 안전 중지

- `viewer-monitor-state.json`이 손상되었거나 필수 필드·내부 참조가 올바르지 않으면
  해당 실행의 자동 감시를 시작하지 않습니다.
- 현재 Viewer보다 새로운 스키마의 파일은 수정하거나 이전 형식으로 덮어쓰지 않고,
  같거나 최신 버전의 Viewer가 필요하다고 안내합니다.
- 파일 읽기 권한이 없거나 다른 프로세스의 잠금으로 접근할 수 없으면 이전 상태를
  정상 상태처럼 사용하지 않고 자동 감시를 중지합니다.
- 손상 파일을 격리한 경우 Viewer를 다시 시작하면 새 기준선을 만듭니다. 격리 자체가
  실패하면 원본을 그대로 보존하고 권한 또는 파일 잠금을 확인하도록 정확히 안내합니다.

화면과 진단 로그에는 원인에 따라 다음 안전한 오류 코드를 구분해 표시합니다.

```text
VIEWER_MONITOR_STATE_CORRUPT
VIEWER_MONITOR_STATE_VERSION_UNSUPPORTED
VIEWER_MONITOR_STATE_UNAVAILABLE
```

원시 예외, 장비 IP, 사용자 이름, 비밀번호와 명령 출력은 진단 로그에 기록하지 않습니다.

## 실행 중 저장 실패와 이력 무결성

- 정상 시작 후 감시 이력 저장이 실패하면 `VIEWER_MONITOR_STATE_WRITE_FAILED`로 표시하고
  이후 자동 감시를 차단합니다. 저장되지 않은 결과를 정상 최신 상태로 계속 표시하지
  않습니다.
- 이벤트 ID와 순번의 중복, 잘못된 다음 순번, 존재하지 않는 이벤트를 가리키는 활성
  장애·포트 상태 등 중첩된 이벤트 구조의 무결성도 로드 시 검증합니다.
- 불완전하거나 모순된 일부 데이터만 선택적으로 받아들이지 않으며, 파일 전체를 하나의
  일관된 상태로 검증합니다.

## 자동 감시와 수동 조회 분리

- 감시 이력 저장소가 안전하게 열리지 않아 자동 감시가 중지되어도 Agent 연결, 장비 관리와
  사용자가 직접 실행하는 읽기 전용 수동 `show` 조회는 계속 사용할 수 있습니다.
- 자동 감시 중지 상태는 기존 대시보드의 장비 상태, 수집기 상태와 안내 영역에서
  `확인 불가` 또는 `시작 안 됨`으로 명확히 구분합니다.
- 저장소 오류를 장비 정상이나 Agent 연결 성공으로 오인하지 않으며, 사용자가 조치하기
  전까지 자동으로 정상 상태로 바꾸지 않습니다.

## 호환성과 운영 영향

- Agent API v4, Viewer 설정 JSON, 장비 저장 JSON과 감시 이력 JSON 스키마 버전은
  변경하지 않았습니다.
- 기존 스키마 v1·v2 감시 이력은 이전과 같이 호환하며, 현재 형식으로 안전하게 읽습니다.
- 화면 구조, Agent·Viewer 설치 순서, 기본 5분 감시 주기, 장비별 세션 제한과 동시 감시
  제한은 변경하지 않았습니다.
- 기본 감시 명령과 수동 조회 명령 검증 정책은 변경하지 않았으며, 운영 장비에는 등록된
  읽기 전용 `show` 명령만 실행합니다.

## 검증

- 손상 JSON과 UTF-8, 미래 스키마, 파일 접근 실패, 격리 실패, 실행 중 저장 실패,
  중첩 이벤트 참조 오류와 기존 v1·v2 파일을 결정적 Fixture로 검증했습니다.
- 저장소가 비정상인 동안 자동 감시는 실행되지 않고 수동 조회는 유지되는지 회귀
  테스트로 확인했습니다.
- Core 85건, Agent 53건, Viewer 321건으로 총 459건의 자동 테스트를
  통과했습니다.
- Release 빌드 경고·오류 0, C# 서식, PowerShell 5.1 구문·설치·복구 계약,
  NuGet 취약 패키지와 Git whitespace 검사를 통과했습니다.

## 보안과 현장 검증 범위

- 이 `-poc` 패키지는 Authenticode 서명이 없는 현장 검증용 프리릴리스입니다.
- 합성 파일 시스템, Mock Agent와 로컬 Fixture로 검증했으며 실제 사내 EDR·AppLocker·
  WDAC 정책과 IES4224GP, IES4028XP, IES4226XP 펌웨어에서는 검증하지 않았습니다.
- 실제 장비 검증은 사내에서 읽기 전용 명령과 단일 장비부터 단계적으로 수행해야 합니다.
