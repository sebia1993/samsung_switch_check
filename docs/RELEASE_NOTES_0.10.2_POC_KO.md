# Samsung Switch Watch 0.10.2-poc 릴리스 노트

## 요약

이번 패치 버전은 새 기능을 추가하지 않습니다. Agent Setup의 실패 롤백이 끝난 뒤
트랜잭션 기록이나 임시 폴더 정리만 실패한 상태를 안전하게 기록하고, 다음 Setup 실행에서
정리를 이어갈 수 있도록 복구 절차를 보강합니다.

Agent API, Viewer 화면과 설정, Telnet 조회, 감시 동작과 설치 흐름은 변경하지 않았습니다.

## Agent Setup 롤백 기록과 정리 재개

- 이전 Agent 프로그램·서비스·방화벽 상태의 롤백이 완료되면 임시 폴더를 지우기 전에
  작업 기록에 `rollback-completed` 단계를 원자적으로 저장합니다.
- 완료 단계 기록 뒤 트랜잭션 기록 또는 `.__staging_*`, `.__failed_*` 임시 폴더 정리가
  실패하면 증거를 보존하고 다음 Setup 실행에서 정리를 다시 시도합니다.
- 정리가 재개될 때는 복원된 Agent 설치 폴더를 다시 실패 폴더로 이동하지 않습니다.
- 완료 기록의 단계·상태 플래그·제품 경로와 실제 설치·백업·임시 폴더 구성이 일치할 때만
  남은 자료를 정리하고 새 설치를 시작합니다.
- 작업 기록과 설정 파일은 임시 파일을 디스크에 강제 반영한 뒤 원자적으로 교체하고,
  교체된 파일도 다시 디스크에 반영한 뒤 다음 단계로 진행합니다.
- 알 수 없는 단계, 모순된 상태 플래그, 남아 있는 백업, 복원되지 않은 설치 폴더 또는
  동시에 존재하는 staging·failed 폴더처럼 안전성을 증명할 수 없는 상태는
  `RECOVERY_REQUIRED`로 중단합니다. 이 경우 서비스와 폴더를 임의로 변경하지 않고 작업
  기록과 복구 자료를 보존합니다.
- 작업 기록 플래그와 다른 백업·실패 폴더 또는 데이터 생성 단계와 맞지 않는 ProgramData
  상태도 서비스 중지 전에 거부합니다.
- 설치 완료 기록이 남아 있더라도 실제 Agent 프로그램이나 기존 ProgramData가 사라졌으면
  백업과 기록을 지우지 않고 `RECOVERY_REQUIRED`로 중단합니다.
- 이전 작업 기록을 읽는 도중 오류가 발생해도 새 트랜잭션으로 오인하여 별도의 롤백을
  실행하지 않습니다.
- 새 작업 기록 형식은 `2`로 올렸습니다. `0.10.2` Setup은 기존 형식 `1`의 정상 단계를
  읽어 복구할 수 있고, 복구를 시작하기 전에 기록을 형식 `2`로 원자적으로 전환합니다.
  구형 `0.10.1` Setup은 새 형식 `2`를 해석하지 않고 중단하므로 복원된 설치 폴더를 잘못
  이동하지 않습니다.

## 호환성과 운영 영향

- 새 사용자 기능, 화면, API, 설정 스키마 또는 장비 명령 정책은 없습니다.
- Agent와 Viewer는 같은 `0.10.2-poc` Release의 ZIP을 함께 사용하십시오.
- Agent 업데이트가 실패했거나 `RECOVERY_REQUIRED`가 표시되면 설치 폴더의
  `.__staging_*`, `.__backup_*`, `.__failed_*` 폴더와 ProgramData의 작업 기록을
  수동으로 이동하거나 삭제하지 마십시오.
- `0.10.2` 설치 도중 복구 자료가 남은 경우에는 구형 Setup으로 되돌리지 말고 동일한
  `0.10.2` Agent ZIP의 Setup을 다시 실행하십시오.
- 파일 잠금이나 보안 제품 차단처럼 일시적인 원인을 해소한 뒤 같은 Agent Setup을 다시
  실행하십시오. 재시도해도 복구가 중단되면 보존된 상태에서 관리자 또는 개발 담당자가
  확인해야 합니다.

## 현장 확인 범위

- 합성 파일 시스템과 로컬 Fixture로 롤백 완료 기록, 기록·임시 폴더 정리 실패, 다음 실행의
  정리 재개와 모순된 상태의 fail-closed 동작을 검증했습니다.
- 실제 사내 PC의 UAC 계정 전환, Windows 서비스와 방화벽 복원, 파일 잠금, 디스크 오류,
  백신·EDR·AppLocker·WDAC 간섭 상태에서는 검증하지 않았습니다.
- 이 `-poc` 패키지는 Authenticode 서명이 없는 현장 검증용 프리릴리스입니다. 보안 정책을
  우회하지 말고 공식 Release의 파일 해시와 사내 승인 절차를 확인하십시오.
- 첫 적용에서는 Agent 한 대에서 정상 업데이트와 복구 중단 시 증거 보존을 확인한 뒤 배포
  범위를 넓히십시오.
