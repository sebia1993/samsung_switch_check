# Samsung Switch Watch 0.9.22-poc 릴리스 노트

## 장비 목록 저장소 실패 시 안전 중지

- `viewer-devices.json`이 손상됐거나 읽기·저장이 불가능하면 기존 장비를 정상이나
  단순 빈 목록으로 표시하지 않고 해당 실행의 자동 감시와 장비 명령을 중지합니다.
- 현재 Viewer보다 새로운 스키마의 파일은 격리, 수정 또는 이전 형식으로 덮어쓰지
  않습니다. `VIEWER_DEVICE_STORE_VERSION_UNSUPPORTED`를 표시하고 같거나 최신
  Viewer를 사용하도록 안내합니다.
- 손상 파일은 원본을 `.corrupt-*` 파일로 보존합니다. 격리 자체가 실패하면 원본을
  그대로 유지하고 `VIEWER_DEVICE_STORE_UNAVAILABLE`로 안전하게 중지합니다.
- 원자 저장이 실패해도 기존 장비 목록을 빈 파일이나 일부 변경 결과로 대체하지
  않습니다.
- 같은 실행에서 정상 장비 목록 파일을 한 번이라도 읽거나 저장한 뒤 파일이
  사라지면 새 빈 목록으로 처리하지 않고 `VIEWER_DEVICE_STORE_UNAVAILABLE`로
  안전하게 중지합니다.

다음 오류 상태는 Viewer를 다시 시작하기 전까지 해제하지 않습니다.

```text
VIEWER_DEVICE_STORE_CORRUPT
VIEWER_DEVICE_STORE_VERSION_UNSUPPORTED
VIEWER_DEVICE_STORE_UNAVAILABLE
```

해당 상태에서는 저장, 삭제, 감시 설정 변경, 계정 해석, 접속 시험과 수동 `show`
조회도 장비에 연결하기 전에 차단합니다.

## 화면 상태와 작업 안내

- 실행 중 장비 목록 저장에 실패하면 다음 감시 주기를 기다리지 않고 기존 장비
  카드를 즉시 `Warning / DeviceStoreUnavailable`로 바꿉니다.
- 정상·감시 장비 수는 0으로 바꾸고 대시보드, 수집기 상태, 미니 창과 작업 안내에
  자동 감시 중지와 안전한 오류 코드를 표시합니다.
- 장비 관리 창은 미래 스키마를 “등록 장비 0대”로 오인하지 않으며, 저장소 오류로
  차단된 접속 시험을 네트워크 접속 실패로 잘못 안내하지 않습니다.
- 구형 Agent 화면에서 v4 Agent로 전환할 때 저장소가 실패해도 이전 Agent의 장비
  카드를 정상 상태로 남기지 않습니다.
- 시작 시 최소화가 설정되어 있어도 장비 목록 저장소 오류가 있으면 메인 창을
  표시합니다.
- 진단 로그는 시작 단계와 실행 중 감시 단계를 구분해 기록하되 장비 IP, 계정,
  비밀번호와 명령 원문은 기록하지 않습니다.

## 감시 공백과 heartbeat 정확성

- 장비 목록 저장소가 실패한 뒤 Viewer를 늦게 종료해도 종료 시각을 마지막 정상
  heartbeat로 덮어쓰지 않습니다.
- 다음 실행은 마지막 실제 감시 시각부터의 공백을 감지하고 기존 기준선을 안전하게
  다시 만듭니다.
- Agent 사전 연결 또는 정상 응답과 장비 목록 저장 실패가 동시에 발생해도 저장소
  상태를 잠금 안에서 다시 확인한 뒤에만 heartbeat를 기록합니다.
- 저장소 실패가 감시 작업 중 발생하면 추가 결과 저장과 다음 감시 주기를 중단합니다.

## 시작 안정성과 복구

- 이전 형식의 평문 사용자 이름을 Windows DPAPI로 이전하는 과정이 실패해도 Viewer가
  시작 단계에서 비정상 종료되지 않습니다.
- 원본 파일을 보존하고 자동 감시·장비 명령을 중지한 뒤 사용자 폴더 권한, 파일 잠금과
  Windows 사용자 프로필을 확인하도록 안내합니다.
- 문제를 해결한 후 Viewer를 다시 시작해야 장비 목록을 다시 읽고 감시를 시작합니다.

## 호환성과 운영 영향

- Agent API v4, Viewer 설정 JSON, 장비 저장 JSON 스키마 v1과 감시 이력 JSON
  스키마는 변경하지 않았습니다.
- 화면 구조, Agent·Viewer 설치 순서, 기본 5분 감시 주기, 장비별 세션 제한과 동시
  감시 제한은 변경하지 않았습니다.
- 기본 감시 명령, 수동 조회 명령 검증과 한 줄 읽기 전용 `show` 정책은 변경하지
  않았습니다.
- Agent와 Viewer는 같은 `0.9.22-poc` 릴리스 ZIP으로 함께 업데이트하는 것을
  권장합니다.

## 검증

- 미래 스키마, 손상 JSON, 파일 읽기·쓰기·격리 실패, DPAPI 보호 실패와 반복 접근을
  결정적 파일 시스템 Fixture로 검증했습니다.
- 저장 실패 직후 화면 경고 전환, 명령 비활성, 접속 요청 0건과 안전한 진단 코드를
  WPF 스모크 테스트로 확인했습니다.
- 지연된 Agent 시작·실패·정상 응답과 저장 실패의 경쟁, 종료 후 heartbeat 보존과
  재시작 감시 공백을 TaskCompletionSource 기반 결정적 테스트로 검증했습니다.
- Core 85건, Agent 53건, Viewer 351건으로 총 489건의 자동 테스트를 통과했습니다.
- Release 빌드 경고·오류 0, C# 서식, PowerShell 5.1 구문·설치·복구 계약,
  NuGet 취약 패키지와 Git whitespace 검사를 통과했습니다.

## 보안과 현장 검증 범위

- 이 `-poc` 패키지는 Authenticode 서명이 없는 현장 검증용 프리릴리스입니다.
- 합성 파일 시스템, Mock Agent와 로컬 Fixture로 검증했으며 실제 사내 EDR·AppLocker·
  WDAC 정책과 IES4224GP, IES4028XP, IES4226XP 펌웨어에서는 검증하지 않았습니다.
- 실제 장비 검증은 사내에서 읽기 전용 명령과 영향이 적은 단일 장비부터 단계적으로
  수행해야 합니다.
