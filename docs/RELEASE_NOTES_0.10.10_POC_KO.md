# Samsung Switch Watch 0.10.10-poc 릴리스 노트

이번 버전은 사내에서 긴 로그를 외부 개발 환경으로 전달하기 어려운 상황을 위해 Agent Setup
실패와 Viewer 연결 실패에 짧은 SWD1 지원 코드를 표시합니다. 기존 Agent API, 장비·자격 증명
저장 방식, 수동 `show` 명령, 감시 데이터와 `SSW_FIELD_DIAGNOSTIC/1` 형식은 변경하지 않습니다.

## 실패 화면의 짧은 지원 코드

- 형식은 `SWD1-XXXX-XXXX-XXXX-XXXX`입니다.
- Agent Setup의 실패와 Viewer의 Agent 연결 실패에서만 표시합니다.
- `지원 코드 · 이 코드만 전달하세요` 아래 읽기 전용 값으로 표시하며 마우스나 키보드로
  선택한 뒤 `Ctrl+C`로 복사할 수 있습니다.
- 별도 복사 버튼을 추가하지 않았습니다.
- 새 작업을 시작하거나 Agent 주소를 바꾸면 이전 코드를 지웁니다.
- 실행 중과 성공 화면에는 표시하지 않습니다.

코드는 인터넷이나 Agent↔Viewer 통신 없이 각 프로그램 안에서 생성합니다. 제품 버전,
컴포넌트, 작업과 허용된 오류·단계·상태 분류만 고정된 짧은 값으로 변환합니다. IP/CIDR,
PC·사용자명, ID·비밀번호, 인증서, 경로, 예외 원문, 장비 명령과 출력은 포함하지 않습니다.

끝의 CRC-8은 전화나 메신저로 옮길 때 생긴 입력 오타를 확인하기 위한 값입니다. 암호화,
전자서명 또는 신원 확인 기능이 아니며 SWD1은 비밀값, 로그인 토큰, 페어링 토큰, 인증서
SHA-256 지문이나 접근 승인 값이 아닙니다.

## 기존 진단 경로와의 구분

세 진단 경로의 역할은 다음과 같이 유지됩니다.

| 표시 또는 작업 | 위치와 조건 | 용도 |
|---|---|---|
| SWD1 지원 코드 | Agent Setup 실패, Viewer 연결 실패 | 전화·메신저로 짧은 장애 분류 전달 |
| `진단정보 복사` | Agent Setup 실패만 | 자세한 비식별 실패 요약을 클립보드로 복사 |
| `익명 진단 저장` | Agent Setup 작업 또는 Viewer 연결 검사 완료 | `SSW_FIELD_DIAGNOSTIC/1` 상세 TXT를 사용자가 선택해 저장 |

SWD1은 기존 두 진단 경로를 대체하지 않습니다. 화면만으로 해결되지 않으면 같은 화면의 오류
코드와, 필요한 경우 사용자가 직접 저장한 익명 진단 TXT를 사내 승인 절차에 따라 전달합니다.

## 호환성과 유지되는 동작

- Agent와 Viewer는 같은 `0.10.10-poc` Release 조합을 사용합니다.
- Agent는 창이나 트레이 아이콘 없이 Windows 서비스로 실행됩니다.
- Viewer는 관리자 권한이나 설치 스크립트가 필요 없는 포터블 실행 파일입니다.
- Agent API는 HTTPS/TCP 18443과 고정 Viewer IPv4 `/32` 경계를 그대로 사용합니다.
- Viewer가 장비 IPv4·ID·PW·선택적 enable PW와 감시 이력을 소유합니다.
- Agent는 요청마다 새 Telnet 세션으로 한 줄 읽기 전용 `show` 명령을 실행하고 종료합니다.
- 수동 장비 명령과 출력은 Viewer 메모리에만 있으며 SWD1이나 익명 진단에 들어가지 않습니다.
- 인증서 지문 또는 페어링 토큰을 사용자가 입력하는 절차는 없습니다.

## 검증 범위와 현장 확인

자동 검증은 SWD1의 고정 벡터, Agent/Viewer payload 왕복, 대소문자·공백·하이픈 정규화,
Crockford 별칭, 한 글자 CRC 오류 거부와 민감정보 비포함을 확인합니다. UI 검증은 실패에만
코드가 나타나고 성공·새 시도·입력 변경에서 지워지는지 확인합니다.

이는 실제 사내 EDR, Windows 서비스, 방화벽 COM, 원격 Viewer 경로와 삼성 스위치 Telnet
동작을 증명하지 않습니다. 사내에서는 다음 순서로 제한적으로 확인하십시오.

1. Agent와 Viewer ZIP을 같은 Release에서 받아 각각 새 로컬 폴더에 완전히 압축 해제합니다.
2. 영향이 적은 시험 PC와 단일 Agent 경로에서 연결 실패를 의도적으로 확인합니다.
3. 실패 화면에 SWD1이 나타나고 선택·복사되는지 확인합니다.
4. 새 시도와 성공 뒤 이전 코드가 사라지는지 확인합니다.
5. 한 글자를 잘못 옮긴 코드는 지원 도구에서 거부되는지 확인합니다.
6. 실제 운영 장비 설정을 변경하지 말고 읽기 전용 조회만 단계적으로 확대합니다.
