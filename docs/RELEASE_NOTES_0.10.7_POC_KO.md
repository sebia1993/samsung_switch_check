# Samsung Switch Watch 0.10.7-poc 릴리스 노트

이번 버전은 새 장비 기능을 추가하지 않고, Agent 설치·업데이트 실패 뒤
`SETUP_ROLLBACK_FAILED`만 반복 표시되어 원인을 구분하기 어려웠던 복구 흐름을 명확하게
정리합니다.

## 별도 이전 상태 복구

Agent Setup은 시작할 때 이전 설치·업데이트의 미완료 작업 기록을 읽기 전용으로 확인합니다.

- 안전하게 복구 가능한 상태이면 `설치/업데이트`를 비활성화하고 `이전 상태 복구`만
  활성화합니다.
- 운영자가 `이전 상태 복구`를 직접 눌러야 복구를 시작합니다.
- 복구가 성공하면 설치 버튼은 다시 활성화되지만 설치나 업데이트를 자동으로 시작하지
  않습니다. 운영자가 검사 결과를 확인한 뒤 새 작업을 별도로 실행합니다.
- 작업 기록이 손상됐거나 파일·서비스 상태가 기록과 맞지 않아 안전성을 증명할 수 없으면
  복구와 설치를 모두 차단하고 Windows 관리자 확인을 요청합니다.
- 새 설치·업데이트 실행 경로도 미완료 작업이 남아 있으면 방어적으로 시작을 거부합니다.

구형 Setup을 실행하거나 설치를 반복해서 누르지 마십시오. 복구 대기 또는 실패 상태의
`Agent.__staging_*`, `Agent.__backup_*`, `Agent.__failed_*` 폴더와
`%ProgramData%\SamsungSwitchWatch-Operations` 작업 기록은 수동으로 삭제·이동·이름 변경하지
않습니다.

## 실패 원인과 복구 단계 분리

설치·업데이트와 rollback이 모두 실패하면 다음 정보를 서로 구분합니다.

- 최초 설치 또는 업데이트 실패 원인
- 서비스 중지, 파일·ACL 복원, 데이터 정리, 서비스 상태 복원, 방화벽 snapshot 복원,
  작업 기록과 증거 정리의 단계별 결과
- 호환성을 위한 최종 `SETUP_ROLLBACK_FAILED`

같은 rollback 오류를 복구 단계 결과와 최종 설치 결과에 중복 표시하지 않습니다. 프로그램
복원과 검증이 완전하지 않으면 이전 Agent 서비스를 다시 시작하지 않으며, 각 방화벽 snapshot은
독립적으로 복원 결과를 남깁니다. 권위 있는 상태 복구가 확인된 뒤에만 rollback 완료 기록과
복구 증거 정리를 진행합니다.

`service-stop-pending` 단계에서 중단된 기존 Agent 업데이트는 아직 이동되지 않은 정상 설치
폴더를 그대로 보존하고 이전 서비스 상태를 복원합니다. journal의 이전 서비스·방화벽
snapshot이 제품 계약과 맞지 않으면 파일이나 서비스를 변경하기 전에 복구를 차단합니다.
예상하지 못한 Windows 오류도 Task 예외로 화면을 이탈하지 않고 `SETUP_UNEXPECTED` 결과로
표시하며 작업 기록을 보존합니다.

## 실패 전용 진단정보 복사

실패 화면에서만 `진단정보 복사`를 사용할 수 있습니다. 별도 진단 파일을 만들지 않고 다음
안전한 요약만 클립보드에 복사합니다.

- 제품 버전과 UTC 시각
- 작업 종류
- 최초 실패와 rollback 단계별 안정 오류 코드
- 작업 기록 형식과 단계
- 필요한 자료의 존재 여부
- Agent 서비스 상태

다음 정보는 복사하지 않습니다.

- 실제 IP/CIDR, PC 이름과 Windows 사용자명
- 절대 경로, 트랜잭션 ID와 서비스 계정
- 방화벽 규칙 이름·주소·원문
- 자격 증명, 인증서, 명령과 장비 출력

## 호환성과 유지되는 동작

- Agent와 Viewer는 같은 `0.10.7-poc` Release 조합을 사용합니다.
- 기존 Agent API, Viewer 장비·자격 증명 소유권과 Telnet 조회 흐름은 바뀌지 않습니다.
- Agent는 창이나 트레이 아이콘 없이 Windows 서비스로 실행됩니다.
- Viewer는 관리자 권한이나 설치 스크립트가 필요 없는 포터블 실행 파일입니다.
- Agent는 설정 변경 명령을 실행하지 않고, 승인된 관리망의 읽기 전용 `show` 명령만
  처리합니다.
- 공개 ZIP에는 PowerShell·CMD 설치 스크립트를 포함하지 않습니다.

## 검증 범위와 현장 확인

자동 테스트와 Mock은 작업 기록 판정, 복구 의존 순서, 실패 원인 분리, 중복 표시 방지와
진단정보 민감정보 제외 계약을 확인합니다. 이는 실제 Windows SCM, 방화벽 COM, ACL, EDR
파일 잠금과 중단된 `0.10.6-poc` 설치 상태를 모두 증명하지 않습니다.

사내 적용 전 관리자 시험 PC 한 대에서 다음을 확인하십시오.

1. 중단된 작업 감지 시 설치가 차단되는지 확인합니다.
2. `이전 상태 복구` 성공 뒤 설치가 자동 실행되지 않는지 확인합니다.
3. 파일 복원이 불완전한 시험에서 이전 서비스를 시작하지 않는지 확인합니다.
4. 복구 실패의 최초 원인과 단계별 원인이 구분되는지 확인합니다.
5. `진단정보 복사` 결과에 실제 주소, 경로, 계정과 방화벽 원문이 없는지 확인합니다.
6. 검증 뒤 영향이 적은 Agent 한 대부터 단계적으로 확대합니다.
